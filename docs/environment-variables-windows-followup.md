# 환경 변수 — 윈도우 쪽 남은 구멍

`src/content/posts/environment-variables/index.md`를 윈도우·리눅스 양쪽 기준으로 고치고 남은 메모다.
2026-09-06 기준. 이 글의 최종 검토는 보류 상태다.

## 무엇이 비어 있나

리눅스 쪽은 「혼동하기 쉬운 것」의 `.bashrc`/`.profile`/cron/ssh 항목이 "누가 언제 읽어서 누구에게 물려주는가"를 답한다.
윈도우 쪽에는 대응 항목이 없다. 「영구 설정은 프로세스 바깥에 있다」의 `setx` 예시가
"현재 창에는 안 보인다"까지만 말하고 멈춰서, **그럼 언제 보이나, 왜 재부팅인가**에 답하지 않는다.

이 글을 쓰게 된 원래 질문이 그 자리였다.

## 채울 내용

재시작이 필요한 이유는 값을 받아야 할 프로세스의 **조상이 낡은 복사본을 들고 있기 때문**이다.
레지스트리를 고쳐도 이미 도는 프로세스의 환경 블록을 덮어쓰는 주체가 없다.
값을 바꾼 쪽은 `WM_SETTINGCHANGE`(`lParam="Environment"`)를 브로드캐스트하고,
이 메시지를 처리하는 프로그램만 레지스트리를 다시 읽어 자기 블록을 새로 만든다.

| 대상 | 새 값을 보려면 | 이유 |
|---|---|---|
| 이미 열려 있는 cmd/PowerShell 창 | 창을 새로 연다 | 알림을 처리하지 않아 영영 다시 읽지 않는다 |
| 탐색기에서 새로 실행하는 프로그램 | 그냥 된다 | 부모인 탐색기가 알림을 받아 갱신했다 |
| 탐색기가 알림을 놓친 경우 | `explorer.exe` 재시작 | |
| 서비스 | 재부팅 | SCM(`services.exe`)의 블록이 부팅 때 만들어진다 |

재부팅이 필요한 게 아니라 낡은 복사본을 쥔 조상을 다시 시작하면 된다.
재부팅은 모든 사슬을 한꺼번에 리셋하는 가장 둔한 방법이라 항상 통할 뿐이다.
로그오프 후 로그인은 사용자 세션 사슬까지, 재부팅은 서비스까지 커버한다.

## 곁가지로 확인해 둔 것

- 영구 저장소는 두 키다. 사용자 `HKCU\Environment`, 시스템 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`.
  시스템 속성 창, `setx`, `[Environment]::SetEnvironmentVariable(..., 'Machine')`은 전부 이 두 키로 가는 서로 다른 입구다.
- `HKCU\Volatile Environment`는 별개다. `USERNAME`, `USERPROFILE`, `APPDATA`, `LOGONSERVER`, `HOMEPATH`가 여기 있고
  로그온할 때 만들어졌다가 로그오프하면 사라진다. 편집기로 고칠 대상이 아니다.
- `Path`는 `REG_SZ`가 아니라 `REG_EXPAND_SZ`다. `%SystemRoot%\system32` 같은 참조를 원문 그대로 담아 두었다가
  환경 블록을 만들 때 펼친다.

## 확인이 남은 것

- **서비스와 SCM 항목은 재현하지 않았다.** 알려진 동작을 적은 것이고, 글에 실으려면
  머신 범위 변수를 하나 만들고 서비스를 재시작해 값이 안 보이는 것과 재부팅 후 보이는 것을 직접 대조해야 한다.
- **리눅스 코드 블록의 실행 조건이 없다.** 배포판도 bash 버전도 적혀 있지 않다.
  특히 「한 명령에만 붙이기」의 "POSIX 모드 bash와 dash에서는 남고 기본 모드 bash에서는 남지 않는다"는
  모드·버전 의존 주장이라 조건이 가장 필요한 자리다. 리눅스에서 확인해 채워야 한다.

## 어디에 넣나

정하지 않았다. 두 갈래다.

- 지금 글의 「영구 설정은 프로세스 바깥에 있다」 뒤에 한 문단과 위 4행 표를 붙인다. 분량은 현재 글의 5% 남짓이라 기본개념 안에 남는다.
- 윈도우 환경 변수가 프로세스에 도달하는 시점만 따로 파고들기로 뺀다. 로그온 세션과 서비스가 각각 언제 블록을 만드는지까지 들어간다.
