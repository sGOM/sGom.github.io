# 그룹 3종 템플릿과 선택 섹션

작성일: 2026-08-09

이 문서는 [글 분할 스펙](2026-08-09-post-split-basics-deepdive-design.md)의 "템플릿 분리" 절을 대체한다.
거기서는 섹션이 고정 목록이었다. 여기서는 필수와 선택으로 나눠 글의 성격에 맞게 고를 수 있게 한다.

## 배경

그룹은 세 개(`기본개념`, `파고들기`, `오답노트`)인데 템플릿은 둘(`concept.md`, `troubleshooting.md`)이다.
`concept.md`가 기본개념과 파고들기 양쪽에 걸쳐 있어, 어느 쪽 글을 쓰는지가 템플릿에서 드러나지 않는다.

더 큰 문제는 섹션이 고정이라는 점이다. `concept.md`는 여섯 섹션을 모두 요구한다. 표와 짧은 설명으로
끝나는 기본개념 글에 `동작 원리`와 `언제 쓰고 언제 안 쓰나`를 억지로 채우게 되고, 반대로 구현 코드를
따라가는 글에는 마땅한 섹션이 없다.

그룹마다 템플릿을 하나씩 두고, 각 템플릿 안에서 섹션을 필수와 선택으로 나눈다.

## 표기 방식

각 섹션 heading 아래에 안내문 한 줄을 두고, 그 줄을 `필수 —` 또는 `선택 —`으로 시작한다.

```markdown
## 핵심 정리

필수 — 표로 한눈에 보이게. 항목, 동작, 차이를 열로 세운다.

## 혼동하기 쉬운 것

선택 — 실무에서 자주 뒤바뀌는 짝이 있을 때.
```

글을 쓰면 이 안내문 줄을 내용으로 갈아치우게 되므로 표시가 파일에 남지 않는다. heading에 마커를
붙이는 방식(`## 왜 필요한가 <!-- 선택 -->`)은 섹션을 채운 뒤에도 마커를 따로 지워야 해서 쓰지 않는다.

파일 맨 위, frontmatter 아래에 규칙을 주석으로 적는다.

```markdown
<!--
선택 섹션은 해당 없으면 지운다. 순서는 글에 맞게 바꿔도 된다.
안내문 줄(필수 — / 선택 —)은 내용으로 갈아치운다.
-->
```

순서를 바꿔도 된다는 점을 명시한다. 선택 섹션이 필수 섹션 사이에 놓여야 자연스러운 경우가 있다.

## templates/basics.md — 기본개념

frontmatter의 `tags`에 `["기본개념"]`을 미리 넣는다.

**필수 두 개.**

| 섹션 | 안내문 |
|---|---|
| `## 핵심 정리` | 표로 한눈에 보이게. 항목, 동작, 차이를 열로 세운다 |
| `## 예시` | 짧은 코드나 상태 변화. 표만 있는 글은 공식 문서 요약과 구별되지 않는다 |

재현과 실행 결과는 요구하지 않는다. 기본개념은 표와 짧은 설명·예시로 정리하는 글이고, 재현이
분량을 차지하기 시작하면 그건 파고들기로 넘길 사안이다.

**선택 아홉 개.**

| 섹션 | 쓰는 때 |
|---|---|
| `## 왜 필요한가` | 모르면 어떤 문제를 겪는지. 정의부터 시작하지 않을 때 |
| `## 용어 정리` | 이름이 비슷해 헷갈리는 용어를 먼저 갈라놓을 때 |
| `## 항목별 설명` | 표 한 줄로 부족해 항목마다 2~3문장이 필요할 때 |
| `## 혼동하기 쉬운 것` | 실무에서 자주 뒤바뀌는 짝이 있을 때 |
| `## 구현체별 차이` | 표준과 실제 제품이 다를 때. DBMS, 브라우저, 런타임 |
| `## 직접 확인` | 짧게 재현해 보일 때. 분량이 커지면 파고들기로 분리한다 |
| `## 언제 어떤 것을 쓰나` | 선택 기준이 있을 때 |
| `## 더 깊이` | 대응 파고들기 글이 있을 때 링크 |
| `## 참고` | 출처 |

파일에 놓이는 순서는 `왜 필요한가` → `용어 정리` → `핵심 정리` → `항목별 설명` → `예시` →
`혼동하기 쉬운 것` → `구현체별 차이` → `직접 확인` → `언제 어떤 것을 쓰나` → `더 깊이` →
`참고`다. 필수 두 개가 중간에 놓인다.

## templates/deep-dive.md — 파고들기

frontmatter의 `tags`에 `["파고들기"]`를 미리 넣는다.

**필수 두 개.** 기존 `concept.md`의 규율을 여기로 옮긴다.

| 섹션 | 안내문 |
|---|---|
| `## 동작 원리` | 내부적으로 어떻게 돌아가는지 |
| `## 직접 확인` | 코드로 재현하고 실행 결과를 넣는다 |

`직접 확인` 아래에 기존 문구를 그대로 유지한다.

```markdown
**이 섹션이 비면 발행하지 않는다.**
공식 문서를 요약한 글은 이미 많지만 직접 재현해 확인한 글은 적다.
```

**선택 열 개.**

| 섹션 | 쓰는 때 |
|---|---|
| `## 전제` | 대응 기본개념 글이 있을 때 링크. 이 글이 어디서 출발하는지 |
| `## 왜 필요한가` | 이 깊이가 왜 필요한지 |
| `## 겉으로 보이는 것` | 표면 동작과 실제가 다를 때. 먼저 표면을 적고 뒤집는다 |
| `## 구조` | 클래스·컴포넌트 관계. 그림이나 순서도 |
| `## 코드로 따라가기` | 실제 구현 코드를 인용해 짚을 때 |
| `## 경계 조건` | 언제 깨지는가 |
| `## 대안과 트레이드오프` | 다른 선택지가 있을 때 |
| `## 언제 쓰고 언제 안 쓰나` | 실무 판단 기준 |
| `## 성능` | 측정값이 있을 때만. 없으면 쓰지 않는다 |
| `## 참고` | 출처 |

파일에 놓이는 순서는 `전제` → `왜 필요한가` → `겉으로 보이는 것` → `구조` → `동작 원리` →
`코드로 따라가기` → `직접 확인` → `경계 조건` → `대안과 트레이드오프` → `언제 쓰고 언제 안 쓰나` →
`성능` → `참고`다. 필수 두 개가 중간에 놓인다.

## templates/troubleshooting.md — 오답노트

이미 `tags: ["오답노트"]`가 들어가 있다. 기존 여섯 섹션을 **전부 필수로 유지**한다.

| 섹션 | 안내문 |
|---|---|
| `## 상황` | 어떤 시스템에서, 무엇을 하다가 마주쳤는지. 3~4문장 |
| `## 증상` | 관측된 사실만 적는다. 로그, 지표, 에러 메시지. 추측은 여기 쓰지 않는다 |
| `## 가설과 검증` | 무엇을 근거로 세웠고, 어떻게 확인했고, 결과가 무엇이었는지 |
| `## 원인` | 왜 그런 일이 일어났는지. 코드나 설정 수준의 근거와 함께 |
| `## 해결` | 바꾼 것과, 바꾼 뒤 지표가 어떻게 변했는지 |
| `## 배운 것` | 다음에 비슷한 상황에서 무엇을 먼저 볼 것인가. 2~3줄 |

`가설과 검증`의 기존 문구를 그대로 유지한다. 이 섹션이 오답노트의 존재 이유다.

```markdown
**틀린 가설도 남긴다. 이 섹션이 이 템플릿의 존재 이유다.**
정답만 적힌 글은 검색 결과와 구별되지 않는다.
```

**선택 다섯 개.**

| 섹션 | 쓰는 때 |
|---|---|
| `## 환경` | 버전이 원인일 때. 라이브러리, 런타임, DB 버전 |
| `## 재현 절차` | 최소 재현 코드나 단계가 있을 때 |
| `## 막다른 길` | 조사했지만 원인이 아니었던 경로. 가설로 정리하기 애매한 것 |
| `## 남은 문제` | 해결했지만 찜찜하게 남은 것 |
| `## 참고` | 출처 |

파일에 놓이는 순서는 `상황` → `환경` → `증상` → `재현 절차` → `가설과 검증` → `막다른 길` →
`원인` → `해결` → `남은 문제` → `배운 것` → `참고`다.

## 함께 바뀌는 것

**`templates/concept.md`를 삭제한다.** `basics.md`와 `deep-dive.md`로 갈라지므로 남길 이유가 없다.

**`CLAUDE.md` 1절**의 템플릿 고르기를 두 갈래에서 세 갈래로 고친다.

```markdown
### 1. 템플릿 고르기

- **기본이 되는 개념을 표와 짧은 설명으로 정리하는 글** → `templates/basics.md`
- **기본개념으로 간단히 설명하기 어렵거나 더 깊이 다루는 글** → `templates/deep-dive.md`
- **실제로 겪은 문제 상황의 파악과 해결 과정** → `templates/troubleshooting.md`

애매하면 물어본다. 임의로 정하지 않는다.

세 템플릿 모두 섹션이 필수와 선택으로 나뉘어 있다. 선택 섹션은 해당 없으면 지운다.
```

3절의 그룹 태그 표와 1절의 템플릿 선택이 같은 세 갈래를 가리키므로, 표현을 일치시킨다.

**`README.md`**의 "템플릿은 두 가지다"를 세 가지로 고친다.

## 검증

- `npm run build`가 통과한다. 템플릿은 `src/content/posts/` 밖에 있어 스키마 검증 대상이 아니지만,
  회귀가 없음을 확인한다.
- `npm test`가 통과한다. 이 작업은 코드를 건드리지 않으므로 22/22가 그대로 나온다.
- `templates/` 아래에 `basics.md`, `deep-dive.md`, `troubleshooting.md` 세 파일만 남는다.
  `concept.md`는 없다.
- 세 템플릿의 frontmatter `tags`에 각 그룹 태그가 정확히 하나 들어 있다.
- 모든 섹션이 `필수 —` 또는 `선택 —`으로 시작하는 안내문 줄로 시작한다. 안내문은 섹션당 한 줄이며,
  `직접 확인`(파고들기)과 `가설과 검증`(오답노트)만 그 아래에 기존 강조 문구를 덧붙인다.
